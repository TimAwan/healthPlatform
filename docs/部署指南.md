# 本机部署指南（Windows）

本文档指导你在自己的 Windows 电脑上把健康管理平台完整跑起来：中间件（MySQL/Redis/RabbitMQ/Nacos）+ 5 个后端微服务 + PC 管理端前端。

---

## 1. 架构与端口总览

| 组件 | 端口 | 说明 |
|------|------|------|
| gateway-service | 9000 | API 统一入口，前端只访问它 |
| auth-service | 9101 | 登录 / JWT / 验证码 |
| system-service | 9102 | 用户 / 角色 / 权限 / 菜单 / 操作日志 |
| doctor-service | 9103 | 医生 / 审核 / 医院 / 科室 |
| file-service | 9104 | 文件上传下载 |
| MySQL 8.0 | 3306 | 4 个库：auth_db / system_db / doctor_db / file_db |
| Redis 7 | 6379 | 验证码、Token 黑名单、权限缓存 |
| RabbitMQ | 5672 / 15672 | 消息（一期仅启动，控制台 15672） |
| Nacos | 8848 | 注册中心 + 配置中心，控制台 http://localhost:8848/nacos |
| 前端（dev） | 5173 | Vite 开发服务器，/api 代理到 9000 |

**启动顺序**：中间件 → system-service → auth-service → doctor-service → file-service → gateway-service → 前端。
（先起 system 是因为 auth 登录时要调它的内部接口；其余业务服务在网关之前起即可。）

## 2. 前置条件检查与安装

### 2.1 已具备（你当前机器）

- JDK 17：实际位于 `D:\Application\JDK`
- Maven 3.9.4：`D:\develop\apache-maven-3.9.4`
- Node.js 22 + npm 10
- Git

### 2.2 必须修复：JAVA_HOME 环境变量

当前系统 `JAVA_HOME` 指向不存在的 `D:\JavaApps\JDK8`，Maven 和 IDEA 会报
`The JAVA_HOME environment variable is not defined correctly`。

修复步骤：

1. `Win + R` 输入 `sysdm.cpl` → 高级 → 环境变量
2. 系统变量中编辑 `JAVA_HOME`，值改为 `D:\Application\JDK`
3. 新开一个终端验证（必须新开，旧窗口不生效）：

```bash
mvn -version
# 输出 Java version: 17 ... runtime: D:\Application\JDK 即成功
```

### 2.3 必须安装：Docker Desktop

1. 官网下载安装：https://www.docker.com/products/docker-desktop/ （Windows 版）
2. 安装时保持默认勾选 **Use WSL 2 instead of Hyper-V**；如提示需启用虚拟化，按提示在 BIOS 开启
3. 安装完成后**重启电脑**，启动 Docker Desktop（任务栏鲸鱼图标变为稳定状态）
4. 验证：

```bash
docker --version
docker compose version
```

> 内存建议：Docker Desktop 默认占用 2GB+，加上 5 个 Java 服务每个约 512MB~1GB，建议本机 16GB 以上内存；可在 Docker Desktop → Settings → Resources 调整。

## 3. 配置环境变量文件

```bash
cd D:\HealthManagementSystem\health-platform
cp .env.example .env        # PowerShell 用：copy .env.example .env
```

`.env` 变量说明（本地开发全部有默认值，可不改直接用）：

| 变量 | 用途 | 默认值 | 生产必改 |
|------|------|--------|----------|
| MYSQL_ROOT_PASSWORD | MySQL 容器 root 密码 | root123456 | 是 |
| DB_USERNAME / DB_PASSWORD | 后端服务连库账号 | root / root123456 | 是 |
| REDIS_PASSWORD | Redis 密码 | redis123456 | 是 |
| RABBITMQ_USER / RABBITMQ_PASSWORD | RabbitMQ 账号 | health / rabbit123456 | 是 |
| JWT_SECRET | JWT 签名密钥 | dev-only-... | 是（≥32 字节随机值） |
| ADMIN_USERNAME | 初始管理员用户名 | admin | — |
| ADMIN_INITIAL_PASSWORD | 初始管理员密码 | Admin@123456 | 是（首次登录后重置） |
| INTERNAL_TOKEN | 服务间内部调用令牌 | dev-internal-token | 是 |
| NACOS_AUTH_TOKEN 等 | Nacos 鉴权 | 见文件 | 是 |
| OSS_* | 阿里云 OSS（prod profile 用） | 空 | 生产必填 |

**重要说明**：`.env` 只被 `docker compose` 自动读取；**Java 服务不会读 .env**，它们读操作系统环境变量，读不到时使用代码里的同款默认值。因此：

- 本地开发**全部用默认值**时，无需任何额外设置；
- 如果你修改了 `.env` 里的 MySQL/Redis/JWT 等值，必须把同名变量同步设为**系统环境变量**（或在 IDEA 运行配置 / 启动命令中注入），否则中间件与服务配置不一致会连不上。

## 4. 启动中间件（Docker）

```bash
cd D:\HealthManagementSystem\health-platform
docker compose up -d
docker compose ps
```

预期 4 个容器全部 `healthy`：health-mysql、health-redis、health-rabbitmq、health-nacos。

验证：

- Nacos 控制台：浏览器打开 http://localhost:8848/nacos ，账号密码均为 `nacos`
- RabbitMQ 控制台：http://localhost:15672 （health / rabbit123456）
- MySQL 首次启动会自动执行 `docker/mysql/init/01-create-schemas.sql` 创建 4 个库

注意：

- **初始化脚本只在数据卷第一次创建时执行**。如果之前起过旧版本的容器，想重新初始化库，执行：
  ```bash
  docker compose down -v   # 会删除 MySQL/Redis/RabbitMQ 全部数据，慎重
  docker compose up -d
  ```
- 镜像拉取慢可在 Docker Desktop → Settings → Docker Engine 中配置国内镜像加速地址。

## 5. 编译并启动后端

### 5.1 编译

```bash
cd D:\HealthManagementSystem\health-platform
mvn clean install
```

预期输出 `BUILD SUCCESS`（9 个模块，55 个单元测试全部通过）。

### 5.2 启动方式一：IDEA（推荐）

用 IDEA 打开 `health-platform` 工程，等待 Maven 导入完成，依次运行 5 个启动类：

| 顺序 | 启动类 |
|------|--------|
| 1 | `com.health.platform.system.SystemServiceApplication` |
| 2 | `com.health.platform.auth.AuthServiceApplication` |
| 3 | `com.health.platform.doctor.DoctorServiceApplication` |
| 4 | `com.health.platform.file.FileServiceApplication` |
| 5 | `com.health.platform.gateway.GatewayServiceApplication` |

> IDEA 里如果提示 datasource 红色警告可忽略（运行时才连库）。若你改过 `.env` 密码，在 Run Configuration → Environment variables 里注入对应变量。

### 5.3 启动方式二：命令行（5 个窗口）

```bash
mvn spring-boot:run -pl system-service
mvn spring-boot:run -pl auth-service
mvn spring-boot:run -pl doctor-service
mvn spring-boot:run -pl file-service
mvn spring-boot:run -pl gateway-service
```

### 5.4 启动完成判定

- Nacos 控制台 → 服务管理 → 服务列表：出现 5 个服务（system-service、auth-service、doctor-service、file-service、gateway-service）
- 快速验证网关：

```bash
curl http://localhost:9000/api/v1/auth/captcha
# 返回 {"code":200,"message":"success","data":{"captchaId":"...","image":"data:image/png;base64,...}}
```

- 首次启动时 system-service 会自动创建初始管理员（控制台打印 WARN 日志：已初始化系统管理员账号）
- 各服务日志同时输出到各自模块 `logs/*.log`

## 8. 日常运维

| 操作 | 命令 |
|------|------|
| 停止后端服务 | IDEA 停止按钮 / 各命令行窗口 `Ctrl+C` |
| 停止中间件 | `docker compose stop` |
| 再启动中间件 | `docker compose start` |
| 彻底删除中间件容器（保留数据） | `docker compose down` |
| 删除中间件 + 全部数据（重置） | `docker compose down -v` |
| 查看中间件日志 | `docker compose logs -f mysql`（或 redis/nacos/rabbitmq） |
| 后端应用日志 | 各服务模块目录 `logs/*.log`（含 request_id） |

## 9. 常见问题

| 现象 | 原因与处理 |
|------|------------|
| `mvn` 报 JAVA_HOME is not defined correctly | 系统 JAVA_HOME 仍指向旧值，按 2.2 修复后**新开终端** |
| `docker: command not found` / 鲸鱼图标异常 | Docker Desktop 未安装或未启动；WSL2 未启用时按官方指引 `wsl --update` |
| `docker compose ps` 里 mysql 不健康 | 多为 3306 端口被本机其他 MySQL 占用：`netstat -ano \| findstr 3306` 找到 PID 后 `taskkill /PID <pid> /F`，或改 compose 端口映射 |
| 服务启动报 Access denied for user 'root' | `.env` 里改过 MYSQL_ROOT_PASSWORD 但服务仍用旧密码 → 同步设置系统环境变量 DB_PASSWORD（见第 3 节说明） |
| Nacos 控制台登录 401 | 确认地址是 `http://localhost:8848/nacos`，账号 nacos/nacos；仍失败则 `docker compose logs nacos` 查看启动错误 |
| 服务注册不到 Nacos | 检查 9848 端口（gRPC）未被防火墙/代理拦截 |
| 前端页面 502 / 请求失败 | gateway-service 未启动；确认 9000 端口在监听 |
| 登录页验证码不显示 | Redis 未启动或 auth-service 未启动；看 auth-service 控制台报错 |
| 登录提示验证码错误 | 验证码 5 分钟有效且一次性，刷新图片重试；系统时间偏差大也会导致 |
| 表不存在 / Flyway 报错 | MySQL 数据卷是旧版本初始化的 → `docker compose down -v` 后重建（注意备份数据） |
| 端口占用（9000/9101/...） | `netstat -ano \| findstr <端口>` 找 PID，`taskkill /PID <pid> /F` |

## 10. 附录：生产部署要点（二期完善，此处仅提示）

- 后端：`SPRING_PROFILES_ACTIVE=prod`，注入生产环境变量（DB/Redis/JWT_SECRET/NACOS_AUTH_TOKEN/INTERNAL_TOKEN/OSS 四件套，全部必改，禁止默认值出生产）
- 文件存储：prod profile 默认走阿里云 OSS（`health.file.storage=oss` + OSS_* 变量）；开发环境为本地磁盘
- 前端：`npm run build` 产出到 `dist/`，用 Nginx 托管并把 `/api` 反向代理到网关，示例：

```nginx
server {
    listen 80;
    server_name your-domain.com;

    location / {
        root /opt/health-platform-web/dist;
        try_files $uri $uri/ /index.html;
    }

    location /api/ {
        proxy_pass http://<网关地址>:9000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

- HTTPS：生产必须 TLS 1.2+（说明书 30 章），证书挂在 Nginx/负载均衡层
- Kubernetes 集群化部署为二期内容（TODO-011），一期代码与配置结构已满足容器化要求
